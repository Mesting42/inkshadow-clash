# 系统交接

## 目录与运行链路

| 文件 | 职责 |
| --- | --- |
| `src/main.ts` | 启动与 requestAnimationFrame；固定 1/60 秒逻辑，切后台不补帧 |
| `src/game.ts` | 应用主状态、模式流程、检查点、奖励/商店组织，不实现画面或碰撞细节 |
| `src/types.ts` | 世界、实体、攻击、存档、平台与视觉事件的数据契约 |
| `src/data.ts` | 攻击、武器、敌人、技能、强化、关卡的平衡与文案 |
| `src/input.ts` | 键盘、重映射、多点触控、模拟摇杆、方向死区和动作边沿 |
| `src/movement.ts` | 角色控制器、重力、接地、单向平台、土狼时间、跳跃缓冲 |
| `src/actions.ts` | 攻击阶段、取消窗口、连段、闪避与实体状态推进 |
| `src/combat.ts` | 攻击范围、有效帧、命中防重、格挡、伤害、霸体与扫掠投掷 |
| `src/entities.ts` | 全新实体工厂与统一状态切换 |
| `src/animation.ts` | 程序姿态、二段 IK、固定肢长、双手握点约束 |
| `src/renderer.ts` | 等比镜头、三主题场景、实体、武器、HUD 以外视觉 |
| `src/skill-vfx.ts` | 三类技能特效的生成、生命周期和独立绘制 |
| `src/icons.ts` | 彩色图标，技能 SVG/Canvas 共用形状 |
| `src/ai.ts` | 敌人进攻协调、平台接近、支援与三名 Boss 行为 |
| `src/world.ts` | 固定关卡拓扑、受约束随机、增援与竞技场生成 |
| `src/rewards.ts` | 奖励抽选、层数上限、被动应用 |
| `src/ui.ts`、`src/style.css` | 语义 DOM 界面、HUD、菜单、触控布局与响应式规则 |
| `src/audio.ts` | 本地合成音色、分离音量、有界音源生命周期 |
| `src/storage.ts` | 版本存档、字段白名单、范围验证与坏档回退 |
| `tests/` | 规则及流程回归 |
| `scripts/simulate.ts` | 只发正常输入的确定种子机器人与长期重开压力检查 |
| `artifacts/` | 本地截图、模拟 JSON、验收证据（不参与生产构建） |
| `dist/` | 静态网页构建输出 |

主链路：Input → Game 编排 → actions/AI → movement → combat/projectiles → 奖励/流程 → UI；Renderer 仅读取状态。技能特效由有效帧产生视觉事件，不能反向调用 damage。

## 坐标与时间

世界 x 向右、y 向下，单位像素；实体的 x 是中心，y 是脚底。速度单位 px/s，加速度 px/s²，计时统一为秒。逻辑固定 60Hz，视觉使用实际帧间隔平滑镜头。Canvas 使用 1280×720 虚拟舞台，按较小缩放比等比居中，额外区域留边，避免平板或高窗口拉伸角色。

## 动作与命中

AttackDef 的 startup / active / recovery 定义三个阶段。Attack 保存独立的 hit Set（同挥击同目标一次）与 procs Set（同挥击的技能视觉、破防回能等只触发一次）。每段连击重新建立 Attack，不能沿用上段命中集合。

默认攻击取消需经过有效帧和 60% 收招；闪避取消需经过有效帧和 28% 收招。输入缓存仅保留 0.15 秒；受击、界面变化、重试清空缓存。空中攻击次数按离地周期限制，落地重置；重复浮空按次数衰减至 25%，Boss 不受普通浮空。

格挡按攻击来源 x 与防守朝向判断，不能防身后。精准防御窗口为 0.16 秒。无敌完全免伤；霸体仍承受伤害但不会被普通攻击打断。玩家短时连续受控两次后获得额外保护，倒地/起身也有保护期。

投掷使用上一帧到当前帧的线段与角色近似碰撞体相交，避免高速越过目标；落地回收的武器保留原耐久并扣除一次损耗。地面拾取依赖 E 的按下边沿，交换旧武器有拾取锁定，不自动反复交换。

## 平台与 AI

单向平台仅检查向下跨越顶部；从下方不碰撞。穿平台请求必须确认当前脚底是 oneWay，不能从实体地基下穿。实体地基额外处理侧面；落入深坑时玩家扣耐久回安全地面，敌人作击败处理，Boss 回收至安全地面。

普通近战同屏最多两名发起攻击；其余保持包围距离。远程弹道可读、有起手。AI 对跳跃平台作高度与水平距离约束，不可达时等待或重定位；普通敌人在玩家倒地/起身时停止进攻。

每个 Gate 拥有固定范围和必要敌人 id。普通封锁三批增援，所有批次清空后才结算一次。增援从两侧场内进入并带较长 AI 起手延迟。Boss 召唤也加入 Gate 必要敌人，避免提前解除封锁。

## 新增内容

1. **动作**：扩展 data.ts 的 AttackDef，决定明确的起手/有效/收招、范围、伤害与击退；在 animation.ts 给出对应关键姿态，检查命中发生时的手/武器位置。新增特殊判定时写规则回归，不把逻辑写入绘制。
2. **武器**：扩展 WeaponId 和 WEAPONS，在 Renderer.weapon 增加握柄原点为 (0,0) 的绘制，加入 icons.ts 图标。双手武器在 animation.ts 通过同一杆轴反解握点，不能直接随意指定第二只手。
3. **普通敌人**：扩展 EnemyId、ENEMIES、AI 分支与随机池；控制生成范围、进攻令牌和平台可达性。外观通过头部、装备与姿态区分。
4. **Boss**：扩展 bossAttack 的招式序列及阶段阈值；不可格挡必须设 unblockable，预警与实际判定同时从数据读取，保留收招反击窗口。
5. **技能**：在 SKILLS 增加消耗、冷却、颜色和动作；在 SKILL_GLYPHS 与 skill-vfx.ts 增加同源图形与视觉事件。视觉只在有效首帧生成一次。训练场自动按 SKILLS 枚举显示技能按钮。
6. **强化**：在 PERKS 明确 id、层数上限、实际效果与图标，在相关系统消费该 id；rewardChoices 会排除满层条目。伤害/回能类效果要确认“每目标”还是“每挥击”。
7. **关卡**：在 LEVELS 增加元数据，并在 createWorld 中设计主线地基、台阶、缺口及奖励支路；所有缺口必须在跳跃能力范围内，所有敌人落点都应在 Gate 场内和真实地基上。

## 平衡调整

优先修改 data.ts 的攻击、敌人、武器、技能数据。移动速度与重力在 movement.ts；玩家基础耐久在 entities.ts/maxHealth；关卡增援数量、随机池和初始延迟在 world.ts。调整后执行 npm test、战役模拟和相应浏览器操作，不只观察数值。

机器人读取得到的预备动作时机精确，且不计菜单思考时间，因此它的时长不能当作普通玩家平均时长。需要真人样本评估 15–25 分钟目标与触屏难度。

## 保存与恢复

存档命名空间为 inkshadow.clash.save.v1。每关入口 snapshot 作为安全检查点，恢复时创建新实体/世界、重置攻击与投掷物、填满能量并给短暂保护；不恢复旧攻击帧。设置和纪录单独校验白名单。未来更改结构应增加版本并写显式迁移，不把任意 JSON 直接展开进实体。

## 测试、部署与限制

启动、构建与操作命令见 README。Cloudflare Pages 使用 dist 静态目录。构建不需要网络素材，也不需要密钥。浏览器拒绝音频自动播放时由首次用户操作解锁 AudioContext。

浏览器尺寸模拟、规则回归、确定种子通关与 45 分钟等价步进压力检查各有不同证据边界，见 TEST_REPORT.md。真机触摸、移动浏览器动态工具栏、真实GPU/音频长时内存、更多真人平衡样本仍需后续设备覆盖。当前没有在线/云端功能和完整布娃娃物理。
