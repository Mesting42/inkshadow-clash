二、游戏定位与完整流程

游戏采用固定侧视角。

玩家扮演一名佩戴短围巾的原创火柴人斗士，穿越被敌对势力控制的城区，利用拳脚、拾取武器和战术强化击败敌人，最终挑战敌方首领。

主流程：
进入游戏 → 操作教学 → 横版探索与战斗 → 拾取武器 → 获得强化 → 选择路线与整备 → 精英战 → 最终 Boss → 胜利结算。

目标体验：
- 按下攻击立即得到清楚反馈。
- 普通玩家可以通过简单输入打出连贯动作。
- 熟练玩家可以通过时机、方向、闪避和空中追击获得更高收益。
- 敌人的攻击可以看懂、躲开和反制。
- 被围攻时有脱身手段。
- 每次开局的武器、强化和部分路线有变化。
- 失败后愿意立刻重试。

一局完整战役控制在约 15–25 分钟，必须有明确起点、最终挑战和胜利结算。

三、视觉方向

采用精致的非像素风 2D 或 2.5D 表现。

角色以深色剪影为基础，通过围巾、护腕、绑带、发光眼部、武器姿态等细节区分身份。

整体表现强调：
- 清楚的角色轮廓。
- 流畅、夸张但有重心的动作。
- 适量速度线与动作残影。
- 短促、有方向的命中特效。
- 有层次的前景、中景与远景。
- 克制的光影与鲜明的区域色彩。

至少制作三个场景区域：

1. 黄昏旧街
- 屋顶、招牌、街巷、天桥。
- 暖色夕阳与长阴影。
- 用于建立基础拳脚和平台操作。

2. 雨夜工厂
- 钢梁、传送设施、管道、仓库与检修平台。
- 湿润材质、工业灯光与机械环境音。
- 增加高低差和场景互动。

3. 高塔决斗场
- 高空走廊、断裂平台、风场和大型建筑结构。
- 清楚的纵向层次与最终战构图。
- 氛围明显高于普通关卡。

不要所有场景只换背景颜色。
不要用满屏光晕、震动和烟雾掩盖动作。
不使用血腥肢解，战斗反馈通过冲击、火花、扬尘、击飞和姿态表现。

四、火柴人造型与动画

火柴人的简洁外观不能成为降低动作质量的理由。

至少需要：
- 明确的头、躯干、肩、肘、手、髋、膝、脚部关系。
- 稳定的肢体长度与连接。
- 清楚的身体朝向。
- 双脚落地与站姿重心。
- 身体旋转、压低、伸展和反作用动作。

至少实现：
- 待机。
- 行走与奔跑。
- 起跳、腾空和落地。
- 蹲身或低姿态。
- 轻攻击连段。
- 重攻击。
- 上挑。
- 空中攻击。
- 下砸。
- 闪避。
- 格挡与精准防御。
- 受击、击退、浮空、倒地和起身。
- 武器拾取、攻击与投掷。
- 胜利与失败。

动画可以采用骨骼、程序化姿态或其他可靠方式，但动作必须具有预备、发力、命中与收招过程。

不要让角色只摆动两根手臂就算完成攻击。
手持武器时，手部与武器握点必须对应，不能明显脱手或穿过身体。

五、移动与平台操作

桌面默认操作：
- A / D：左右移动。
- Space：跳跃。
- J：轻攻击。
- K：重攻击。
- L：闪避。
- I：格挡，配合时机触发精准防御。
- E：拾取、交互或交换武器。
- Q：投掷当前武器。
- U：主动技能。
- S＋Space：从允许下落的单向平台下落。
- Esc：暂停。

支持方向键替代移动，提供按键说明与合理的键位调整。

移动要求：
- 起步和停止灵敏。
- 跳跃高度、水平控制和落地反馈稳定。
- 提供适量土狼时间和输入缓冲。
- 默认只使用一次跳跃，特殊强化可以明确增加空中能力。
- 角色可以站上平台、穿过单向平台底部并正确落在顶部。
- 平台边缘不抖动，不无故滑落。
- 不能穿地、卡墙或在墙角无限悬空。

摄像机：
- 平滑跟随。
- 适度观察移动前方。
- 不频繁上下晃动。
- 不露出关卡外部空白。
- Boss 战和竞技场采用适合的固定或受限范围。
- 镜头缩放后保持战斗距离可读。

六、基础战斗与连招

战斗基于确定的角色状态与攻击阶段：
- 起手。
- 有效攻击。
- 收招。
- 受击。
- 闪避。
- 格挡。
- 倒地。

至少实现：

1. 轻攻击连段
- 连续输入形成三至四段连招。
- 不同段动作和击退效果不同。
- 最后一段有清楚终结反馈。

2. 重攻击
- 起手更慢，伤害或破防更强。
- 不能通过无限连按取消所有收招。

3. 上挑
- 通过明确组合输入将可浮空敌人击起。
- 操作方式在教程和说明中清楚展示。

4. 空中攻击
- 可以对浮空目标追击。
- 有限制，避免无限空连。

5. 下砸
- 空中配合方向与重攻击触发。
- 落地形成小范围冲击。
- 有明确收招和风险。

6. 闪避
- 短距离位移。
- 有冷却或体力消耗。
- 无敌时间与视觉一致。
- 不穿过实体墙。

7. 格挡与精准防御
- 正确朝向可以减轻普通攻击。
- 在攻击到来前的短窗口内防御，触发精准防御。
- 精准防御提供短暂反击机会。
- 特定不可格挡攻击用明显颜色、图案或动作提示。

攻击取消规则需要明确：
- 允许在合适窗口衔接下一段或闪避。
- 不允许所有动作随时取消，导致无成本无限攻击。
- 输入缓冲不能在受击结束后自动连续播放过期指令。

七、命中、受击与物理击飞

命中判定必须独立于视觉特效。

每个攻击具有：
- 实际攻击范围。
- 有效时间。
- 伤害。
- 击退。
- 硬直。
- 浮空或倒地效果。
- 对同一目标的命中次数规则。

要求：
- 只在有效攻击阶段造成伤害。
- 同一次普通挥击对同一敌人只命中一次。
- 多段攻击单独定义各段判定。
- 武器轨迹与攻击范围基本一致。
- 高速位移或投掷物使用扫掠检测，避免穿透。
- 背后目标不能被没有覆盖到的前方攻击误伤。
- 攻击特效不能代替实际命中判断。

受击需要有：
- 姿态变化。
- 清楚的方向。
- 短促停顿。
- 适量镜头震动。
- 击退或浮空。
- 声音。
- 耐久即时变化。

物理表现原则：
- 正常战斗由稳定的角色控制器管理。
- 被击飞、倒地或击败时可以使用受约束的物理或程序化惯性。
- 不把完全失控的布娃娃当作正常战斗控制。
- 敌人倒地后有合理保护和起身流程。
- 多次浮空存在衰减或脱离机制，避免无限连。
- 玩家不能被普通敌人无间断硬直到死。
- 落入深坑或被挤压时有明确处理，不永久卡在场景中。

八、武器拾取与使用

至少制作五类武器：

1. 短棍
- 攻速快，范围适中。
- 适合快速连段。

2. 长杆
- 范围较长。
- 适合控制多个敌人。
- 贴身或收招存在弱点。

3. 重锤
- 攻速慢。
- 强击退、破防与范围压制。
- 有明显重量感。

4. 双刃或短刃
- 动作灵活。
- 单次范围较小。
- 强调连击与空中衔接。

5. 投掷器械
- 有明确弹道与数量限制。
- 用于打断远程敌人或制造进攻机会。

武器需要改变：
- 持握姿态。
- 轻重攻击动作。
- 范围。
- 起手与收招。
- 空中攻击。
- 音效和命中特效。

徒手也必须完整可玩，不能没有武器就明显失去基本战斗能力。

武器可以具有有限耐久：
- 耐久清楚显示。
- 耗尽后有破损反馈并自动回到徒手。
- 投掷武器有实际飞行、碰撞与落地。
- 拾取或交换时显示对象与操作提示。
- 地面武器不能在角色脚下无限闪烁或反复自动交换。

九、敌人设计与 AI

至少制作七种敌人：

1. 普通斗士
- 基础近战连击。
- 用于建立战斗节奏。

2. 敏捷刺客
- 擅长快速接近和闪避。
- 攻击前有可读动作。

3. 重装打手
- 移动较慢。
- 有霸体或防御阶段。
- 需要重击、绕后或精准反击。

4. 长杆守卫
- 正面控制范围大。
- 收招后存在机会。

5. 远程投掷手
- 保持距离。
- 使用可躲避、可观察的投掷物。

6. 盾牌敌人
- 正面防御。
- 能被破防、绕后或特定技能克制。

7. 支援敌人
- 为其他敌人提供强化或恢复。
- 优先击败有战术意义。

AI 需要：
- 识别平台和可行走区域。
- 合理接近玩家。
- 不在平台边缘无限尝试不可达动作。
- 跳跃能力受规则约束。
- 在攻击前对齐合理距离与高度。
- 不隔着地板或墙体近战命中。
- 在玩家倒地或过场期间停止不公平追击。

加入进攻协调：
- 普通难度下限制同时发起近战攻击的敌人数。
- 其他敌人可以包围、调整位置或等待机会。
- 不能所有敌人同一帧从屏幕外攻击。
- 远程攻击和高伤害动作有足够预警。

十、关卡与场景互动

战役至少包含六个完整关卡，分布在三个区域。
每关包含探索移动、平台段和战斗段，避免只有连续封闭房间。

- 触发机关前给玩家清楚提示。

场景伤害遵循统一规则，不能只对玩家生效而没有说明。

十一、局内构筑与奖励

每次战后或关键节点提供三选一强化。

至少设计十二种被动强化，形成不同路线，例如：
- 轻攻击终结段附带冲击。
- 重击破防后恢复少量体力。
- 精准防御后下一次攻击强化。
- 空中连击提高落地攻击效果。
- 投掷武器命中后缩短技能冷却。
- 闪避穿过攻击后获得短暂增益。
- 连击达到一定阶段恢复少量护盾。
- 武器耐久降低时提高特定能力。
- 击败精英后获得一次临时保护。
- 徒手状态提高机动性。
- 倒地起身后短暂减伤。
- 击破场景物获得额外资源。

至少制作三种可选择主动技能：
- 冲击掌：近距离击退与打断。
- 影步突袭：快速接近并攻击。
- 震地爆发：消耗能量，对周围敌人形成压制。

主动技能一次装备一种，替换时有明确说明。

强化需要能实际改变玩法，而不是全部增加几个百分比伤害。
叠加规则和上限明确，避免无限控制或永久无敌。

商店或整备点可以提供：
- 恢复。
- 武器。
- 修理武器。
- 被动强化。
- 主动技能。
- 有限次数的保命道具。

所有商品和奖励提供真实图标与预览，不能只有细线图标和一行文字。

十二、随机与重玩性

基础关卡采用经过设计的结构，保证平台和战斗质量。

每局可以变化：
- 战斗区域的敌人组合。
- 部分战斗房顺序。
- 奖励支路。
- 武器位置。
- 商店商品。
- 强化选项。
- 精英词缀。
- 场景事件。

不能为了随机而生成无法完成的跳跃或必死组合。
主线路径必须可达，奖励不能生成在地图外或实体内部。

随机不应破坏教学顺序、Boss 登场和最终结局。

十三、Boss 战

至少制作三个有独立动作设计的章节 Boss，最后一个为最终首领。

Boss 设计方向：

1. 铁拳守门人
- 强调重击、冲锋与地面震荡。
- 通过躲避和破绽建立基础 Boss 体验。

2. 长兵器统领
- 强调攻击距离、连续动作与平台位置。
- 玩家需要观察节奏，寻找近身机会。

3. 影刃首领
- 具有多个阶段。
- 使用位移、连斩、空中攻击和有限召唤。
- 最终阶段明显提升强度，但保留清楚预警和反击窗口。

每个 Boss 需要：
- 独立外观和动作轮廓。
- 至少三种攻击方式。
- 可辨认的预备动作。
- 阶段变化。
- 明确的受击与破防反馈。
- 合理的霸体和控制抗性。
- 不能被简单无限连击锁死。
- 不能无预警从屏幕外瞬移命中。

击败最终 Boss 后停止敌方伤害和生成，进入完整胜利演出与结算。

十四、竞技场与训练

除战役外，再完成：

A. 竞技场挑战
- 在专门设计的场地抵挡连续敌人。
- 波次之间获得短暂整备和强化。
- 不同波次有不同组合。
- 保存最高波次和最佳成绩。
- 场地具有平台与可交互内容，不是空白矩形。

B. 训练场
- 可查看按键。
- 练习轻重连段、上挑、空连、闪避与精准防御。
- 可以切换武器。
- 训练目标显示实际命中与连击信息。
- 可随时退出。

本次聚焦单人对 AI，不扩展在线多人、匹配和服务器排行榜。

十五、手机、平板与桌面适配

桌面使用键盘，手机和平板提供横屏触控。

触屏布局：
- 左侧移动区。
- 右侧轻攻击、重攻击、跳跃、闪避。
- 格挡、技能与交互使用清楚的辅助按钮。
- 支持多点触控，移动、跳跃和攻击可以组合。
- 提供适合触屏的组合输入辅助，例如方向配合重攻击触发上挑。
- 不要求玩家同时按下四个小按钮才能完成基础连招。
- 拾取与投掷可使用明确的情境切换，但不能含义不明。

按钮大小、间距和位置合理，不遮挡角色与敌人。
适配安全区域、圆角、刘海和浏览器工具栏。

竖屏时提供横屏引导并暂停当前战斗。
不支持方向锁定的浏览器仍能正常使用横屏页面。
支持调整触控按钮大小或透明度。

十六、UI、声音与反馈

界面采用与动作世界一致的设计，清楚、克制、有辨识度，避免明显 AI 模板感。

至少完成：
- 主菜单。
- 战役选择与继续。
- 竞技场入口。
- 训练场。
- 装备与技能预览。
- 强化选择。
- 商店。
- 暂停。
- 设置。
- 胜负结算。

HUD 显示：
- 玩家耐久。
- 体力或能量。
- 武器与耐久。
- 主动技能。
- 当前目标。
- 连击。
- Boss 血条。

不要让伤害数字、连击提示和特效遮住敌人的攻击预备动作。

声音至少包含：
- 脚步、起跳和落地。
- 拳脚挥动与命中。
- 各类武器的攻击和碰撞。
- 格挡、破防和精准防御。
- 闪避、技能和击飞。
- 环境破坏。
- Boss 阶段变化。
- 菜单、购买、失败和胜利。

提供音乐与音效独立音量，以及震动、闪光和特效强度设置。

十七、存档、状态与性能

本地保存：
- 战役检查点。
- 当前装备与构筑。
- 关卡完成状态。
- 竞技场纪录。
- 设置与教程状态。

继续游戏从安全检查点恢复，不在敌人攻击生效帧直接恢复。
存档有独立命名空间与版本标记。
损坏存档需要安全处理。

页面失焦或切后台自动暂停。
暂停时同步停止：
- 角色与敌人。
- 攻击判定。
- 投掷物。
- 技能持续时间。
- 机关。
- 波次与关卡计时。

重试后清理旧敌人、攻击判定、掉落物、音效和临时状态。

使用稳定时间步进或等价方案，避免不同刷新率改变战斗速度。
回收离场特效、残骸和投掷物，限制对象数量。
长时间竞技场游玩不能持续增加内存。

十九、实际游玩与验收

必须启动游戏并实际操作，不能只确认构建成功。

重点验证：
1. 桌面与触屏能完成移动、跳跃、攻击和闪避组合。
2. 攻击只在有效阶段造成伤害。
3. 同一挥击不会重复伤害同一目标。
4. 武器轨迹与判定一致。
5. 上挑、空连、下砸与落地状态正确。
6. 玩家不能被普通敌人永久硬直。
7. Boss 不会被简单无限连击锁死。
8. 格挡方向、精准防御和不可格挡提示正确。
9. 平台、墙体与落差不会使角色永久卡住。
10. 敌人能正确处理高低差与不可达位置。
11. 封锁战斗能够正常解除。
12. 武器拾取、投掷、损坏和替换正常。
13. 强化、购买和奖励不会重复结算。
14. 暂停、重试、切后台和继续游戏没有旧状态残留。
15. 竞技场长时间运行后仍然稳定。
16. 主流程能从开局完成最终 Boss 并进入胜利结算。

自动化测试可以辅助验证动作状态、伤害、奖励和关卡规则，但不能直接调用胜利函数冒充通关。

不能实际执行的设备验证要如实说明，不得声称已经测试。

最终交付：
- 完整源码、素材与配置。
- 可构建的静态网页版本。
- 启动与构建命令。
- 本地预览地址。
- 电脑与触屏操作说明。
- README 和交接文档。
- 已实现内容。
- 实际测试结果。
- 明确的已知限制。

最终成果必须是一款非像素风、纯横版平台战斗、动作流畅、打击清楚，拥有完整闯关、武器、构筑、竞技场与最终 Boss，并能在电脑和触屏设备游玩的火柴人格斗游戏。
